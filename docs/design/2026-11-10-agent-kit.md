# Agents fix; only the gate merges
Status: accepted    Owner: Duy    Date: 2026-11-10
Base: Design A, with B's reusable workflows, gate-checked attested evidence and identity split, and the attacker's fixes.

## Intent
Any repo can be onboarded in one step so its production errors and feature tickets are fixed by cloud agents 24/7, and nothing merges unless it passes checks the agent cannot override.
- I1 Building and fixing take Duy's time from design and features. I2 Production errors wait for a human.
- I3 Agents claim "fixed" from passing tests or screenshots while the real outcome is wrong (a save that never persisted).
- I4 Feature knowledge is lost between agent runs.
- I5 Onboarding = one command plus Duy reviewing the 3-5 key journeys it proposes.
- I6 A known past bug is reproduced in a fresh cloud machine, fixed, checked through the real app and stored data, and arrives as a PR with rerunnable evidence.
- I7 An error from Sentry, Datadog or similar becomes a PR or a written triage with no human.
- I8 Only the merge gate merges, and only change classes listed in a versioned policy file.
- I9 Coding runs on Cursor Cloud Agents; Grok Bot holds per-feature conversations.
- I10 The Mac mini runs the deciding agents and sends coding work to Cursor through its API (exception: D5 fallback).
- I11 Prod deploys only from main; Slack is read-only for agents; never push to others' branches; independent review before paid compute.
- I12 Personal and work share one Cursor/Grok account. I13 Approvers are Duy, other people, and the Cursor automation (the automation's approval never counts as human).
- I14 Non-goal: copying the video stack (a bot per feature on day one; three cleanup passes per fix).
- I15 Non-goal: auto-merging auth, payments, migrations, tenancy or destructive changes in phase 1.
- I16 The automation may merge only when the gate passes and the class is on the auto list.
- I17 First trial repo: none yet (yukon-commons later).
- I18 The system measurably improves from outside signals (Duy's edits, review comments, reverts within 14 days, gate failures, false greens); every improvement lands as a PR with before/after proof, approved by a human.

## Facts (verified 2026-11-09/10; * = inherited placement, re-decided below)
- Cursor v1 API (beta): create, follow-up, list, cancel, artifacts; no webhooks; ~20 req/min. Grok/Composer use the included pool; Claude/GPT bill from credit.
- Grok Bot: one shared VM per user, no public API, no completion callback, cannot reach MCP servers on the Mac.
- GitHub: a required check can be bound to one App; skipped and neutral count as success; no merge queue on personal private repos; never run PR code with privileged tokens.
- *Mac mini: FileVault on, no auto-login, so nothing user-level runs after a reboot until a console login; agents run as admin `duy` next to 0600 credential files; no Cursor API key exists.
- Layr-Labs is enterprise; Duy is a member, not an owner, so its rulesets and App installs need an org owner.
- pstack create/maintain-verification-skill writes `verify-<app>` skills and a `features/` map. Supabase branches are data-less, seeded from `seed.sql`; Vercel previews point at prod Supabase.

## Scenarios
- Sentry error at 03:00 → issue within one dispatcher tick (≤ 10 min), Cursor run claimed on the next tick, PR or triage in < 2 h, zero human steps. (I2, I7)
- The same error fires 500×, or is replayed 50× → one issue, one active run. (I7, INV-8)
- Mac mini locked for 2 days → after 30 min the dispatcher sends default runs itself; the gate keeps working. (I7, I10)
- PR claims fixed but the save never persists → base journey's data assertion fails → `agent-gate` red. (I3, I6)
- PR edits policy, a workflow, a journey or the seed → class `governance` → human approval only. (I8, I16)
- PR carries a hand-edited `evidence.json` → attestation mismatch → red. (INV-6)
- Kit ships a new SHA → each repo gets one bump PR in a day; repos on the previous schema keep passing. (I5)
- Onboarding → `gh agent-kit init owner/repo` opens one PR; Duy reviews 3-5 journeys in < 30 min. (I5)

## Decisions
- **D1 Kit = public `yudduy/agent-kit`: reusable workflows pinned by commit SHA + `gh agent-kit init`** (I5; create; one-way)
  Holds `verify.yml` and gate code, the policy schema and floor, the pinned pstack version, and the extension. `init` opens one onboarding PR adding thin callers `uses: yudduy/agent-kit/.github/workflows/verify.yml@<40-hex>`, `.agent-kit/policy.yml`, `.agent-kit/journeys/`, `.cursor/environment.json`, `.cursor/skills/verify-<app>/`, `docs/features/`, and CODEOWNERS lines. It registers the repo in agent-control and starts one Cursor create-verification-skill run that proposes the journeys in that PR. Updates are SHA-bump PRs. A repo the adapter (C1 `app`) cannot run is rejected at `init`. Not chosen: copied template (no update path), submodule (agents fumble it), mutable tags (`@v1` can move under every repo).
  Confirmation: every caller `uses:` is a 40-hex SHA equal to `policy.kit_ref`; onboarding a scratch repo yields exactly one PR.
- **D2 Merge authority = `agent-gate` App run from private `yudduy/agent-control`** (I8, I13, I16; create+ban; one-way)
  The App key is a secret of environment `merge-gate`, limited to main. The gate workflow (cron 5 min + `workflow_dispatch`) lists open PRs in registered repos, reads everything through the API, never checks out or runs PR code, and posts check `agent-gate` (C5) on the head SHA. When it passes, the App merges through the API with `sha=head`. Rulesets: `agent-gate` required and bound to the App id, no bypass actors (admins included), strict up-to-date branches, merge queue where the plan allows. Not chosen: key on the Mac mini (full-access agents read PR text), gate inside each repo (any workflow can fake the name).
  Tripwire: cron lag > 30 min → App webhook receiver. Confirmation: INV-1, INV-2 checks.
- **D3 Identities: agents lose Duy's** (I11, I12, I13; rule; one-way)
  Mac mini deciders get a fine-grained token limited to issues and PR comments. Agent PRs are authored by a bot identity (bot account or App, O2). An approval counts only from a login in `approvers` that is a user, not the PR author or any commit author/committer, given on the exact head SHA. Duy approves from his MacBook or phone. Separate Cursor API keys for dispatcher, Mac mini and onboarding, each revocable alone; spend caps live in the dispatcher because the account is shared (I12).
  Confirmation: INV-4, INV-5 checks.
- **D4 Intake and dispatch = one writer: an Actions workflow in agent-control** (I2, I7, I11; create+rule; one-way)
  `dispatch.yml` (cron 5 min + issue events) runs in environment `dispatch` under one global concurrency group (this also serializes each repo). Each tick: (1) stop if `AGENT_KIT_PAUSED` is `true`; (2) pull new Sentry/Datadog issues through read APIs and upsert one issue per fingerprint (C3); (3) for each issue that is ready, reserve caps (1 run per repo, 3 global, daily $), write the claim (C3), then call Cursor create with the attempt id in the run name; (4) reconcile ambiguous claims through Cursor `list` before any retry. Default models: Composer/Grok. A paid model needs label `agent:paid-ok` from an approver (I11). Escalation after 2 failed attempts or a cap hit: triage comment, `agent:needs-human`, GitHub assignment + email, never Slack. Seer handoff and native Cursor Sentry triggers stay off. Not chosen: Mac mini router (stops on reboot), serverless router (new server, non-atomic upserts).
  Confirmation: INV-8 replay; `agent-kit doctor` reports Seer and native triggers off.
- **D5 Mac mini decides and steers; holds no state of record** (I10, I7; rule; one-way)
  Deciders read `agent:needs-decision`, post a decision comment (C3), and steer live runs with follow-ups. Run creation stays with the dispatcher. They post a heartbeat (C4). If it is older than 30 min, the dispatcher sends the default "reproduce, then fix or write triage" run itself (explicit exception to I10). After the first slice works, agents move to a separate non-admin macOS user with file credentials.
  Confirmation: with the decider user logged out for 1 h, a test error still yields a run.
- **D6 Evidence = attested `evidence.json` from the kit's verify workflow; agent output is advisory** (I3, I6; create; one-way)
  The kit's `verify.yml` runs on `pull_request` on an unprivileged runner with no secrets. Job `build` builds the candidate image. Job `observe` runs kit code only: it starts the candidate container and a DB container seeded from base, drives base-branch journeys, runs base data assertions straight against the DB, and runs the PR's new regression specs as untrusted evidence. Job `attest` (no candidate code; `id-token`/`attestations: write`) hashes and attests `evidence.json` (C2). The gate trusts the attestation signer and the base inputs, never the file's word. Screenshots and Cursor artifacts are for humans. Rerun: `gh agent-kit verify --sha <head> --scenario <id>`.
  Confirmation: INV-6 test; a seeded "UI says saved, DB unchanged" mutant fails.
- **D7 Policy = `.agent-kit/policy.yml` from base + a kit floor repos can add to but never remove from** (I8, I15; rule; one-way)
  The gate computes the class from the compare API diff; the most restrictive class wins; unmatched paths → `review`. Phase-1 auto list: `docs` and `kit-bump` only. Error fixes need a human approval, and the gate posts a shadow verdict on them. A class is added to the list only after 10-20 replayed past bugs show shadow = human outcome. Derived doc PRs never trigger another doc update. **Conflict:** a kit bump edits `.github/workflows/`, which INV-9 bars from auto-merge. The invariant wins, so kit bumps need an approval until Duy rules (O1).
  Confirmation: INV-9 unit tests; a PR adding `migrations` to `auto_merge` stays blocked.
- **D8 Feature knowledge lives in `docs/features/<feature>.md`; Grok Bot only reads it** (I4, I9, I14; rule; two-way)
  A post-merge Cursor automation opens a `docs` PR for each touched feature. One Grok Bot per repo in phase 1.
- **D9 Data = synthetic seed + Sentry-event fixtures; no prod credentials anywhere agents or verifiers run** (I6, I11; ban; one-way)
  The seed generator and fixtures are `governance` paths. Banned: prod DB URLs or keys in Cursor environments, on verify runners or on the Mac mini; previews used as verification. Confirmation: INV-7 doctor scan.
- **D10 Learning loop** (I18; process; one-way)
  A weekly read-only harvest job in agent-control turns signals into cases (C6). A class counts once it has 2 real cases. A fresh agent proposes a fix with pstack /correct and /reflect at the highest level that works: check > verify-skill fix > eval case > small skill-text edit. Proof is a case built from the real failure that fails before and passes after, plus no regression on the full suite. Prose edits are judged blind against the old version by another model family. Duy merges. Not adopted: Cursor continual-learning plugin, Bugbot auto-learned rules in the gate, Grok Bot approval-rule cards that touch merge or policy, unattended memories holding rules.
  Confirmation: INV-11, INV-12, INV-13 checks.
- **D11 Operations: audit, pause, support window** (I8; rule; one-way)
  Audit: gate decisions are check runs plus one JSON line per decision appended to branch `decisions-log` in agent-control (ruleset: no force-push, no deletion). Pause: repo variable `AGENT_KIT_PAUSED=true` in agent-control stops dispatch and auto-merge; the gate still posts verdicts. Support: the gate accepts evidence schema n and n-1; older fails closed with "bump kit to a supported version".

### C1 Policy file v1
```yaml
version: 1
kit_ref: <40-hex>                  # must equal every caller `uses:` SHA
approvers: [yudduy]                # human logins; Bot-type accounts are rejected
app:                               # adapter; init rejects a repo it cannot fill
  build: "docker build -t app ."   # run in job `build` only
  start: {port: 3000, health: /healthz}
  db: {image: postgres:16, seed: .agent-kit/seed/seed.sql}
classes:                           # repo classes; matched by path globs and/or added-line regex
  billing-ui: {paths: ["src/billing/**"], floor: payments}   # `floor:` adds to a floor class
floor_extra: {auth: {paths: ["src/session/**"]}}             # add-only; no removal key exists
auto_merge: [docs, kit-bump]       # v1: subset of {docs, kit-bump}; floor classes rejected
required_checks: ["ci / test"]     # missing, skipped, neutral or pending = fail
journeys:
  - id: save-profile
    areas: ["src/profile/**"]      # required when the diff touches an area
    spec: .agent-kit/journeys/save-profile.spec.ts
    data_assertions:
      - {id: name-persisted, sql: "select name from profiles where id = 'seed-user-1'", expect: [{name: "Ada"}]}
caps: {runs_per_repo: 1, daily_usd: 20, max_attempts: 2}   # can lower, never raise, the kit caps
```
Floor classes (kit-defined, never auto, repo cannot remove): `auth`, `payments`, `migrations`, `tenancy`, `destructive` (deleted files, `DROP|TRUNCATE|DELETE FROM`, `rm -rf`), `governance` (`.agent-kit/**`, `.github/**`, `.cursor/**`, CODEOWNERS, AGENTS.md, CLAUDE.md, seed and fixtures). Kit classes: `docs` (`docs/**`, `*.md` outside governance), `kit-bump` (only `uses:` SHA lines and `kit_ref` change), `review` (default). Precedence: governance > destructive > migrations > tenancy > payments > auth > review > kit-bump > docs. An invalid file fails the gate.

### C2 Evidence file v1
```json
{"schema": 1, "repo": "owner/name", "pr": 12, "head_sha": "<40-hex>", "base_sha": "<40-hex>",
 "kit_ref": "<40-hex>", "policy_sha": "<blob sha of base policy.yml>", "journeys_sha": "<tree sha of base .agent-kit/journeys>",
 "run": {"id": 1, "attempt": 1, "workflow_ref": "yudduy/agent-kit/.github/workflows/verify.yml@<kit_ref>"},
 "env": {"runner_image": "ubuntu-24.04/<version>", "app_image_digest": "sha256:…", "db_image_digest": "sha256:…", "seed_hash": "sha256:…"},
 "scenarios": [{"id": "save-profile", "source": "base", "ui_result": "pass",
   "data_assertions": [{"id": "name-persisted", "sql_sha256": "…", "expected": [{"name": "Ada"}], "observed": [{"name": "Ada"}], "pass": true}],
   "result": "pass", "trace": "traces/save-profile.zip"}],
 "regression": [{"id": "fp-3f9a…", "spec": "tests/regress/fp-3f9a.spec.ts", "trusted": false, "fail_on_base": true, "pass_on_head": true}],
 "artifacts": [{"name": "traces/save-profile.zip", "sha256": "…"}],
 "result": "pass"}
```
A scenario passes only if its UI step passes and it has ≥ 1 data assertion, all passing. The gate rejects the file unless: the attestation subject is its sha256 and the signer is `run.workflow_ref`; `head_sha` is the PR head and `base_sha` the current base; `kit_ref` equals base `policy.kit_ref`; `policy_sha` and `journeys_sha` match base; every journey for a touched area is present with `result: pass`; artifact hashes match. `regression` entries are shown to humans and feed the shadow verdict; they never pass the gate alone.

### C3 Intake labels and markers v1
Labels: `agent:incident` (one per fingerprint), `agent:needs-decision`, `agent:decided`, `agent:claimed`, `agent:running`, `agent:pr-open`, `agent:triaged`, `agent:ignored`, `agent:needs-human`, `agent:paid-ok`. Only the dispatcher sets `claimed`, `running`, `pr-open`; only deciders set `decided`, `ignored`.
Issue body (dispatcher-written; `fp` = first 16 hex of sha256 of `<source>:<source issue id>`):
```
<!-- agent-kit:intake v1 fp:3f9a1c0d7e2b4a65 source:sentry src-id:4512345678 first-seen:2026-11-10T03:00:00Z -->
```
Decision comment (decider login only): `<!-- agent-kit:decision v1 {"action":"fix|triage|ignore","model":"composer-1","prompt_sha256":"…"} -->` then the prompt.
Claim comment, written before the Cursor call: `<!-- agent-kit:claim v1 {"attempt":"<uuid>","at":"<iso>"} -->`; after create: `<!-- agent-kit:run v1 {"attempt":"<uuid>","cursor_id":"…"} -->`. A claim with no run line after 10 min → Cursor `list` by attempt id; found → record it, not found → one retry with a new attempt.

### C4 Heartbeat v1
One comment on the pinned issue "Mac mini heartbeat" in agent-control, edited in place every 5 min:
```
<!-- agent-kit:heartbeat v1 {"host":"mac-mini","accepting":true,"deciders":["claude","codex","opencode"],"open_decisions":2} -->
```
Stale = the comment's server `updated_at` is older than 30 min, or `accepting` is false → D5 fallback.

### C5 Gate check v1
Name `agent-gate`, posted by the App on the head SHA. Conclusion is `success` or `failure`; never `neutral` or `skipped`. `success` needs: not paused, a valid C1 on base, a valid C2, every `required_checks` entry `success` on head (missing, pending, skipped, neutral, cancelled or timed out = fail), branch up to date, and either class ∈ `auto_merge` or a C3-valid approval on head. Summary ends with a fenced JSON block, also appended to `decisions-log`:
```json
{"v": 1, "repo": "owner/name", "pr": 12, "head_sha": "…", "base_sha": "…", "kit_ref": "…", "policy_sha": "…",
 "class": "review", "classes_hit": ["review"], "evidence": "ok|missing|mismatch|unsupported-schema",
 "required_checks": {"ci / test": "success"}, "approval": {"by": "yudduy", "sha": "…"},
 "conclusion": "failure", "shadow": "would_merge|would_not", "reasons": ["class review needs a human approval"]}
```
`shadow` is what the gate would conclude if the class were on the auto list.

### C6 Learning case line v1
One JSON line per case in `learning/cases.jsonl` on the `decisions-log` branch:
```json
{"v": 1, "id": "case-2026-11-10-3f9a1c0d", "at": "2026-11-10T09:00:00Z", "source": "github|gate|sentry",
 "signal": "duy_edit|review_comment|revert_14d|gate_failure|false_green", "repo": "owner/name", "pr": 12,
 "evidence": "https://github.com/…", "excerpt": "≤ 280 chars", "proposed_class": "slug"}
```
`false_green` = the gate passed and, within 14 days, the PR was reverted or the same `fp` reopened.

## Risks (premortem)
